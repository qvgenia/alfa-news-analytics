# Alfa Business Analytics

Сервис персонализированной новостной аналитики для бизнеса. Проект объединяет новостную ленту под профиль клиента, извлечение фактов из новостей и семантический поиск по PDF-отчётам.

## Основные возможности

### 1. Персональная новостная лента
- Получение новостей из подключённых источников.
- Ранжирование новостей с учётом профиля клиента.
- Извлечение фактов из новостей с помощью LLM-шлюза.

### 2. Факты из новостей
- Выделение фактов из текста новости.
- Нормализация и устранение дубликатов.
- Возврат фактов вместе с новостями в ответе API.

### 3. Поиск по PDF-отчётам
- Поиск информации в PDF-отчётах.
- Разбиение документов на фрагменты.
- Семантический поиск по текстовым фрагментам и сохранённым эмбеддингам.

## Технологии

- Python
- FastAPI
- Pydantic
- SQLAlchemy и Alembic
- PostgreSQL и pgvector
- Sentence Transformers
- LLM через совместимый с OpenAI API-шлюз

## Запуск проекта

### 1. Клонирование репозитория

```bash
git clone https://github.com/qvgenia/alfa-news-analytics.git
cd alfa-news-analytics/alfa-business-analytics
```

### 2. Создание виртуального окружения

Для Windows и Git Bash:

```bash
python -m venv .venv
source .venv/Scripts/activate
```

### 3. Установка зависимостей

Если в репозитории есть `requirements.txt`:

```bash
pip install -r requirements.txt
```

Если зависимости устанавливаются через `pyproject.toml`, используйте предусмотренный проектом способ установки.

### 4. Настройка окружения

Создайте локальный `.env` на основе `.env.example` и заполните необходимые параметры.

Для работы с базой данных настройте подключение к PostgreSQL с расширением pgvector. Для извлечения фактов настройте параметры LLM-провайдера.

**Не добавляйте `.env` с секретами в Git.**

### 5. Запуск API

```bash
python -m uvicorn app.main:app --reload
```

Документация API после запуска доступна по адресу:

- Swagger UI: `http://127.0.0.1:8000/docs`
- Проверка состояния: `http://127.0.0.1:8000/health`

## Демо-режим

Для демонстрации предусмотрены три синтетических профиля клиента, хранящиеся в `app/demo/profiles.json`. Они загружаются и валидируются через `app/demo/profile_store.py`.

Демо-маршруты позволяют выбирать профиль без получения клиентского профиля из PostgreSQL.

### Список доступных профилей

```http
GET /demo/profiles
```

### Персональная новостная лента

```http
GET /demo/feed?client_id=demo-client-001
```

Также доступны профили `demo-client-002` и `demo-client-003`.

Демо-профили предназначены для демонстрации и не содержат реальных данных клиентов.

> Демо-маршруты не требуют PostgreSQL для загрузки профиля. При этом получение новостей, извлечение фактов и другие интеграции могут требовать доступных источников данных и настроек окружения.

## Основные API-маршруты

| Маршрут | Назначение |
|---|---|
| `GET /health` | Проверка доступности сервиса |
| `GET /feed` | Персональная новостная лента по клиентскому профилю |
| `GET /demo/profiles` | Список демо-профилей |
| `GET /demo/feed` | Новостная лента на основе демо-профиля |
| API группы `clients` | Работа с клиентскими профилями |
| API группы `reports` | Поиск по отчётам |
| API группы `assistant` | Маршруты ассистента |

Полные параметры запросов и схемы ответов доступны в Swagger UI.

## Данные и документы

PDF-отчёты для поиска размещаются в каталоге `data/reports`, если этот каталог используется в текущей конфигурации приложения.

Для семантического поиска используются векторные представления фрагментов документов. Сохранение эмбеддингов в PostgreSQL позволяет повторно использовать уже рассчитанные представления.

## Структура проекта

```text

├── agent/       # Маршруты ассистента
├── clients/     # Клиентские профили и сервисы
├── db/          # Модели и подключение к БД
├── demo/        # Синтетические демо-профили
├── llm/         # LLM-шлюз
├── news/        # Получение новостей и извлечение фактов
├── rag/         # Поиск по PDF-отчётам
├── ranking/     # Ранжирование новостей
├── main.py      # Приложение FastAPI
└── contracts.py # Модели данных и контракты API
```
